# Theme and asset security

## Security boundary

A Horune theme is untrusted declarative data. It may influence clock appearance and bounded animation, but it must never invoke a system action, access filesystem/network APIs, load arbitrary code, or change scheduler state. Sleep, shutdown, and lock remain explicit desktop-native operations confirmed by the local user.

The same validation rules apply to local files, free community themes, paid themes, remixes, and updates. Ownership is not a trust signal.

## Current enforcement

`ThemeManifestV1` is a strict Zod object. Unknown fields are rejected. IDs, colors, lengths, opacity, effects, FPS choices, canvas size, and layer count/geometry are bounded. The schema has no field for:

- JavaScript or WebAssembly;
- arbitrary HTML or CSS;
- URLs, network requests, deep links, or executable protocols;
- filesystem paths or shell commands;
- scheduler actions or automatic activation.

The current editor imports JSON only and caps input at 256 KiB before parsing. It renders validated fields through React; it does not use `dangerouslySetInnerHTML`, `eval`, dynamic modules, or a webview pointed at creator content.

## Planned asset pipeline

Binary asset import is not implemented yet. Before enabling it, both local clients and backend ingestion must enforce these stages:

1. Check declared and sniffed file type; reject mismatches and polyglots.
2. Enforce per-file (2 MiB) and per-theme (8 MiB) compressed limits.
3. Decode with maintained libraries and enforce width/height (maximum 2048×2048), pixel, frame, duration, and decoded-memory budgets.
4. Strip metadata and re-encode raster images to a canonical form.
5. Generate a static fallback for animated content.
6. Require the creator to declare a license/source category and optional attribution; preserve it in publishing metadata.
7. Hash canonical bytes and use content-addressed asset IDs rather than author-controlled URLs.
8. Re-run validation after upload and before publishing, installation, or update.

The constants already exported by `theme-schema` are initial client guards, not a substitute for server validation.

## Format policy

| Format | Current | Planned acceptance rules |
| --- | --- | --- |
| Theme JSON | Supported | Strict `ThemeManifestV1`, 256 KiB, no unknown fields |
| PNG/WebP | Not yet supported | Decode, dimensions/bytes/memory check, metadata strip, re-encode |
| GIF | Not yet supported | All raster checks plus ≤120 frames, bounded duration/FPS, static fallback |
| SVG | Not yet supported | XML parser and allowlist; no script/events/external refs/foreignObject; flatten or rasterize |
| Figma | Planned converter | Verified API/export input mapped to supported manifest fields; unsupported-node report |
| HTML/CSS | No runtime support | A future isolated, allowlisted converter may emit a manifest; source never executes |
| JavaScript/WASM | Forbidden | No conversion or runtime execution |

## SVG threats to reject

- `script`, event attributes, `foreignObject`, animation elements outside an explicit allowlist;
- external images, fonts, stylesheets, URL references, data URLs, and network-loaded filters;
- entities/DOCTYPE, recursive references, extreme path/point counts, oversized view boxes;
- expensive filter chains, masks, nested transforms, and decompression bombs.

Rendering a sanitized SVG should use canonical output generated by the validator, never the original source bytes.

## GIF and animation budgets

Animated assets must be evaluated using decoded cost, not compressed file size alone. Validation includes frame count, total pixels across frames, duration, effective FPS, disposal behavior, and peak decoded memory. Themes exceeding device or battery policy receive a static fallback or are rejected; the user-visible motion mode always overrides creator preference.

## External conversion

Converters are import tools, not plugin runtimes. They should run in a restricted process/service with network disabled except for an explicitly authorized source fetch, strict CPU/memory/time limits, and no access to Tauri commands. Their output enters the ordinary manifest/asset validation pipeline. Conversion warnings must name omitted or approximated nodes.

## Reporting

Security findings should follow [`SECURITY.md`](../SECURITY.md). High-priority cases include validation bypasses, external resource loading, unsafe SVG behavior, archive/decompression bombs, entitlement bypasses, and any path from theme data to native action execution.
